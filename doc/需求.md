## 1. 项目概述

本工具旨在开发一个高效的**批量邮箱管理系统**。用户可以通过特定的文本格式批量导入 Outlook 账号，系统将通过 IMAP/POP3 协议及官方 API，实现邮件接收、内容检索、标签分类、定时令牌刷新（Token Refresh）等功能，并对外提供标准 API 供第三方系统调用。

------

## 2. 核心功能需求

### 2.1 账号批量导入（数据解析）

- **需求描述**：系统需支持通过文本框复制粘贴或上传 `.txt` 文件的方式批量导入账号。
- **分隔符规则**：默认以 `----` 4个连字符作为字段分隔符，导入时支持自定义分隔符。
- **字段解析映射**： 根据提供的数据样例，解析规则定义如下：
  1. **邮箱账号**：`user@example.com`
  2. **邮箱密码**：`example-password`
  3. **Client ID（客户端ID）**：`00000000-0000-0000-0000-000000000000`
  4. **Refresh Token（刷新令牌）**：`example-refresh-token`

------

### 2.2 邮箱管理与组织

- **邮箱搜索**：支持通过**邮箱账号（模糊查询）\**或\**所属标签**快速筛选和定位邮箱。
- **标签管理（Tagging）**：
  - 支持为单个或多个邮箱批量添加/删除自定义标签（如：`业务A`、`待处理`、`测试组`）。
  - 一个邮箱可同时拥有多个标签。

------

### 2.3 邮件获取与同步（协议与 API）

- **多协议支持**：
  - **后端通道**：支持配置 **IMAP** 或 **POP3** 协议进行基础邮件收取。
  - **OAuth2.0 认证通道**：利用导入的 Client ID 和 Refresh Token，走微软 Graph API 或 Outlook REST API 获取邮件。
- **定时令牌刷新（Token Maintenance）**：
  - 由于微软的 Access Token 有效期较短，系统需在后台建立**定时任务（Cron Job）**。
  - 使用导入的 `Refresh Token` 定时（如每 50 分钟）向微软认证服务器请求最新的 `Access Token`，确保邮件获取通道持续可用，无需人工干预。

------

### 2.4 对外开放 API（API 接口服务）

系统需作为中间件，为其他系统或脚本提供标准 HTTP API：

- **接口功能**：通过传入指定参数，获取特定邮箱的邮件列表或邮件详情。
- **推荐接口设计**：
  - `GET /api/v1/emails?account={email_address}&tag={tag_name}`（获取邮件列表）
  - `GET /api/v1/email/detail?account={email_address}&mail_id={mail_id}`（获取单封邮件的 HTML/正文内容）
